# 需求文档记录规范

本文档定义 Wegent 中“新增需求必须有独立文档记录”的执行规则。

## 适用范围

以下变更必须新增单独文档页，不能只零散补充到已有综述页中：

1. 新功能或新工作流
2. 用户可感知的交互变化
3. 新的第三方平台或集成能力
4. 新的配置方式、鉴权方式或运行前置条件
5. 新的运维行为或发布约束
6. 会影响排障路径的行为变化

## 基本要求

每次新增需求时，交付物必须同时包含：

1. 代码实现
2. 对应测试
3. 独立文档页
4. 相关入口页或索引页中的链接

未完成上述四项时，该需求不应视为完整交付。

## 文档放置规则

按内容性质选择文档位置：

- 用户如何使用：放在 `docs/zh/user-guide/`
- 开发实现与约束：放在 `docs/zh/developer-guide/`
- 部署、运行、发布：放在 `docs/zh/deployment/`
- 故障排查：放在 `docs/zh/troubleshooting.md` 中增加入口，并链接到独立说明页

如果一个需求同时涉及“用户使用”和“开发约束”，至少新增一篇主文档，并在另一侧文档中增加链接和简述。

## 独立文档的最低内容

每篇需求文档至少应包含：

## 背景

说明这个需求解决什么问题，为什么要增加。

## 行为变化

明确变更前后差异，避免读者只能从代码推断。

## 使用方式或接入方式

给出最小可执行示例、配置样例或操作步骤。

## 限制与边界

写清楚不支持什么、依赖什么、失败时会表现成什么。

## 关联文档

链接到相关设置、排障、架构或测试文档。

## 推荐流程

新增需求时，建议按以下顺序执行：

1. 先实现代码与测试
2. 再新增中文文档页
3. 在相关 README / guide / troubleshooting 中补链接
4. 最后补英文版本

## 常见误区

### 只改 README，不新增独立文档

这会导致后续需求堆叠后难以检索，不符合本仓库规范。

### 只写实现细节，不写行为变化

读者无法快速理解“为什么需要这个改动”和“实际影响是什么”。

### 只有中文或只有英文

规范要求先写中文，再补英文；不能长期缺失另一种语言版本。
